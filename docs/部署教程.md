# 听己 · 部署教程

听己装在**你自己的设备**上（NAS、服务器或电脑），你就是它的管理员。它不提供任何在线服务，也不自带任何音源或音频——分析的是你自己的音乐。

两种装法，选一种：

- **飞牛 NAS**：在应用中心搜索「听己 · AI音乐助理」安装（上架后可用）。
- **其他 NAS / Linux**（群晖、威联通、极空间、Unraid、普通主机）：用 Docker Compose，步骤见下。

需要：x86_64 设备，Docker 与 Docker Compose v2，建议空闲内存 4 GB 以上。

---

## 一、用 Docker Compose 安装

1. 在 NAS 上建一个文件夹，例如 `/vol1/1000/Docker/tingji`，把 [`docker-compose.yml`](../docker-compose.yml) 和 [`.env.example`](../.env.example) 放进去，把 `.env.example` 改名为 `.env`。
2. 打开 `.env`，只需改一行——你的音乐文件夹：

   ```ini
   TINGJI_MUSIC_DIR=/vol1/1000/音乐
   ```

3. 在这个文件夹里执行：

   ```sh
   mkdir -p data models
   docker compose up -d
   ```

4. 查看初始化口令（只在创建第一个管理员时用一次）：

   ```sh
   docker logs tingji
   ```

   日志里「听己初始化口令：XXXX-XXXX-XXXX」后面就是。
5. 浏览器打开 `http://NAS的IP:18000`，填口令，设置管理员用户名和密码。

> 群晖、威联通等用图形界面的 Docker 也行：新建「项目 / Compose」，粘贴 `docker-compose.yml`，再在环境变量里填 `TINGJI_MUSIC_DIR`。

## 二、第一次使用

登录后首页会一步步引导，顺序是：

1. **下载分析模型**：「模型管理」里一键下载（约 1.3 GB，只需一次）。不方便联网的可以离线导入。
2. **扫描曲库**：「曲库连接」里你的音乐文件夹会自动出现，点扫描。几千首歌一般几分钟能浏览。
3. **分析歌曲**：「曲库分析」开始声音与歌词分析。整库首次分析耗时较长（与 CPU 有关），可以选择闲时或定时运行，随时暂停。
4. **生成推荐**：选一个你喜欢的歌单作参考，听己从你的曲库里挑相似的歌。

可选：

- **接入飞牛音乐、Plex、Emby、Jellyfin、Navidrome、极音乐**：「曲库连接」→ 添加媒体库，填地址和账号。添加后听己会自动比对文件对应关系，已对应的推荐曲目可交给播放器（和音屿）播放。飞牛音乐与 Plex 另支持经确认后新建歌单并读回核对。
- **添加音源**（用于补全缺失的歌）：「音源管理」里粘贴洛雪（LX）脚本地址或上传脚本文件，保存后自动检查、通过即启用。也支持局域网里自建的音源服务。音源由你自行选择与负责，听己不内置任何音源。
- **大模型助手**（用一句话描述想听什么）：「小己助手设置」里选常用服务、填你自己的密钥，点「测试连接」。默认关闭，费用和数据发送由你自行决定。

## 三、给家人开账号

「账户管理」里生成邀请码，新成员使用访问码自行设置密码。邀请创建的账户默认受限；管理员随后逐项开放曲库、歌单、在线功能及其他权限，并配置可用文件夹、共享音源与每日额度。密码遗失时，可在账户列表选择成员后生成一次性重置码；重置后原会话和设备授权失效。

## 四、连接音屿（手机、电视播放器）

- **只在家里用**：在 `.env` 里填

  ```ini
  TINGJI_NATIVE_LAN_URL=http://NAS的局域网IP:18001
  ```

  执行 `docker compose up -d` 后，在听己网页「客户端连接」里生成配对码，到音屿里填 `http://NAS的局域网IP:18001` 和配对码即可。
- **出门也要用**：需要你自己的域名和 HTTPS 反向代理（如 Lucky、Nginx Proxy Manager、FRP），把设备端口反代出去，再在 `.env` 里填 `TINGJI_NATIVE_PUBLIC_URL=https://你的域名`。两项都填时，音屿在家走内网、在外走外网。

音频始终走你自己的媒体服务器，不经过听己。

## 五、多个音乐文件夹

在 `docker-compose.yml` 里删掉 `TINGJI_MUSIC_DIR` 那一行挂载，改为每个文件夹挂到 `/music/<名字>`：

```yaml
      - /vol1/1000/华语:/music/华语
      - /vol2/1000/古典:/music/古典
```

听己会把每个文件夹识别为一个曲库，名称就是 `/music/` 后面的名字。

## 六、升级、备份、卸载

- **升级**：改 `.env` 里 `TINGJI_IMAGE` 的版本号，执行 `docker compose pull && docker compose up -d`。数据库会自动迁移。
- **备份**：停止容器后备份 `data` 文件夹（账号、分析结果、歌单都在里面）。`models` 可重新下载。
- **卸载**：`docker compose down`，数据仍在 `data`、`models` 里，确定不要了再删。
- **搬到另一台机器或换了音乐的挂载方式**：把 `data`、`models` 整个复制过去，照上面装好后先执行
  `docker compose run --rm tingji python -m tingji.rebind_mounts --apply`
  再 `docker compose up -d`，已有的分析结果不会作废。

## 七、常见问题

| 问题 | 处理 |
| --- | --- |
| 打开网页提示无法连接 | `docker ps` 看 tingji 是否在运行；`docker logs tingji` 看报错 |
| 忘了初始化口令 | `docker logs tingji`；口令 24 小时内有效，过期执行 `docker compose exec tingji python -m tingji.bootstrap --reset-token` |
| 扫描后看不到歌 | 检查 `TINGJI_MUSIC_DIR` 路径，以及 `PUID`/`PGID` 是否有读取权限 |
| 下载入库、改标签提示没有写入权限 | `.env` 里 `TINGJI_MUSIC_MODE=rw`，并确认 `PUID` 对音乐文件夹有写权限 |
| 首次分析很慢 | 在「系统 → 性能」选择已扫描的文件夹并确认后，读取最多 3 首做本机校准；记录仅适用于当前设备、资源与模型。整库任务可选轻量、闲时或定时运行，已有有效特征会复用 |
